# api Module

> **Living document.** Read this before modifying the module. Update it in the same change whenever the module's behavior, endpoints, files, or dependencies change.

**Source:** `api/` · **Last verified:** 2026-08-03

## Purpose

`@paltalabs/api` (`api/package.json:2`) is the backend workspace — a Fastify server plus a standalone background worker. `src/app.ts` builds a dependency-injected Fastify instance: CORS, a public `/health` route, an authenticated scope guarded by the `auth` module's `authPlugin` with the `wallet`/`intents`/`payments`/`history`/`vault`/`ramp` modules' routes registered inside it, and a global typed-error handler. `src/server.ts` is the real HTTP process entry (loads env, fails fast without a sponsor key or the four `ETHERFUSE_*` credentials, opens the DB pool, builds the production Privy verifier + Stellar-Horizon gateway + Soroban-RPC gateway + Privy user resolver + Etherfuse ramp provider + parses the sponsor keypair, listens). `src/worker.ts` is a SEPARATE process entry — the indexer's poll loop (Horizon-payments poll, then a ramp-status poll reconciling pending `on_ramp`/`off_ramp` order rows against Etherfuse when the four `ETHERFUSE_*` credentials are set, chain-only otherwise — `docs/modules/api-indexer.md`), no HTTP surface, own DB pool. `src/index.ts` is now unused (superseded by `server.ts`) but not yet deleted. It also has a Postgres schema (via Drizzle ORM) and connection helper. Feature code lives under `api/src/modules/<name>/` (`sponsor`, `auth`, `wallet`, `intents`, `payments`, `history`, `indexer`, `vault`, and `ramp` exist). Workspace-level runtime config (`src/lib/`, `src/config/`), the Postgres/Drizzle layer (`src/db/`), and one-off spike scripts (`scripts/`) also live here. **This doc covers only the workspace root** (bootstrap, config, workspace-level scripts) — it is not a catch-all for feature submodules, which get their own doc (see `docs/modules/api-sponsor.md`, `docs/modules/api-auth.md`, `docs/modules/api-wallet.md`, `docs/modules/api-intents.md`, `docs/modules/api-payments.md`, `docs/modules/api-history.md`, `docs/modules/api-indexer.md`, `docs/modules/api-vault.md`, `docs/modules/api-ramp.md`).

## How to run

Local dev (real HTTP server, one merchant flow at a time via a browser/Postman):
1. `docker compose up -d db` (repo root) — starts Postgres. If port `5432` is already occupied by an unrelated container on this machine, override it: `DB_HOST_PORT=5439 docker compose up -d db`, and set a matching `DATABASE_URL` for every subsequent command (`postgres://paltalabs:paltalabs@localhost:5439/paltalabs`).
2. `pnpm --filter @paltalabs/api db:migrate` — applies `api/drizzle/`'s migrations.
3. Ensure `SPONSOR_SECRET_KEY` and the four `ETHERFUSE_*` variables are set in the repo-root `.env` (`server.ts` fails fast without any of them — see Gotchas).
4. `pnpm --filter @paltalabs/api dev` (or root `pnpm dev`, which runs every workspace's `dev` script in parallel) — starts the Fastify server on `PORT` (default `3000`).
5. `pnpm --filter @paltalabs/api worker` (or root `pnpm worker`) — starts the indexer's poll loop **in a separate terminal**; not started by `dev` (see Gotchas/`docs/modules/api-indexer.md`).

Headless end-to-end proof (`scripts/e2e-api.ts`, no browser, no separate server/worker process — everything runs in one script):
1. Steps 1–2 above (Postgres up + migrated).
2. `E2E_BYPASS_DID=<any did:privy:...-shaped string> DATABASE_URL=<as above, if overridden> pnpm --filter @paltalabs/api e2e:api` — `E2E_BYPASS_DID` is required (the script refuses to run without it, and refuses under `NODE_ENV=production`). Any value works: if it matches a `merchants.privyDid` already in the DB (e.g. one seeded manually for a prior indexer-module test run — see that module's Testing section), `POST /wallet/provision` reuses that row; otherwise it creates a new one. `SPONSOR_SECRET_KEY` does not need to be set for this path — the script falls back to `docs/evidence/spike-keys.secret.json`'s `sponsor` field if the env var is blank (see the script's own header doc comment for the full rationale: the auth/wallet-resolver bypass, why the bypass is needed at all, and why the proof payment's destination is the registry asset's issuer (USDC) rather than the sponsor).
3. On success, the script prints evidence (tx hash, activity-feed counts, no secrets/DIDs/wallet ids) to the console — see the script's own header doc comment for the exact fields recorded.

## Endpoints / Public surface

| Method | Path | Response | Notes |
|---|---|---|---|
| `GET` | `/health` | `200 {status: 'ok'}` | Liveness check, public — registered directly on the root instance, outside the authenticated scope (`api/src/app.ts:71`). |

All routes registered inside the authenticated scope (`api/src/app.ts:145-153`) require `Authorization: Bearer <Privy access token>` — see `docs/modules/api-auth.md`. That currently means `POST /wallet/provision`, `GET /wallet`, `POST /intents/:id/complete`, `POST /payments`, `GET /activity`, `GET /vault/position`, `POST /vault/deposit`, `POST /vault/withdraw`, `GET /ramp/onboarding`, `POST /ramp/onboarding/start`, `POST /ramp/onboarding/kyc-launch`, `POST /ramp/onboarding`, `POST /ramp/payin/quote`, `POST /ramp/payin`, `GET /ramp/payin/:orderId`, `POST /ramp/payin/:orderId/simulate`, `POST /ramp/payout/quote`, and `POST /ramp/payout` — see `docs/modules/api-wallet.md`, `docs/modules/api-intents.md`, `docs/modules/api-payments.md`, `docs/modules/api-history.md`, `docs/modules/api-vault.md`, and `docs/modules/api-ramp.md` for their request/response shapes (not duplicated here, per this doc's workspace-root-only scope).

Error envelope (all routes, via the global handler `api/src/app.ts:155-169`):
- Thrown `AppError` → `{code, message, details?}` (omitted when `details` is `undefined`) with `error.statusCode`.
- Any other thrown value → `500 {code: 'internal_error', message: 'internal error'}`; the real error is passed to `app.log.error` only, never serialized to the client.
